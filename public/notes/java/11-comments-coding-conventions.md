# COMMENTS AND CODING CONVENTIONS

## Concept Introduction

Comments code explain karne ke liye hote hain. Compiler comments ignore karta hai.

Coding conventions code ko readable aur professional banate hain.

---

## Types of Comments

### Single-line Comment

```java
// This is a single-line comment
```

### Multi-line Comment

```java
/*
 This is a multi-line comment
*/
```

### Documentation Comment

```java
/**
 * This method displays user details.
 */
```

Documentation comments se `javadoc` documentation generate ho sakti hai.

---

## Coding Conventions

Common Java naming rules:

| Element | Convention | Example |
|---------|------------|---------|
| Class | PascalCase | `StudentDetails` |
| Method | camelCase | `displayName()` |
| Variable | camelCase | `studentAge` |
| Constant | UPPER_CASE | `MAX_SIZE` |
| Package | lowercase | `com.example.app` |

---

## Best Practices

- Meaningful names use karo.
- Proper indentation rakho.
- Unnecessary comments mat likho.
- Class name capital letter se start karo.
- Method/variable name small letter se start karo.

---

## Interview Questions

**Q1: Are comments compiled?**

No. Compiler comments ignore karta hai.

**Q2: What are Java naming conventions?**

Class uses PascalCase, methods and variables use camelCase, constants use UPPER_CASE.

**Q3: What is Javadoc comment?**

Javadoc comment `/** */` se likha jaata hai and documentation generate karne ke kaam aata hai.
